# 벤딩·컷팅 계산기 비교 분석 (2026-09-23)

앱의 튜브 벤딩·전선관 벤딩·튜브 컷팅 셈을 읽어 정리하고, 앱 코드를 베끼지 않고
공개된 방식(스웨즈락 수동 벤더 설명서, Greenlee/Klein 벤딩 차트, 배관 공제 관행)
대로 기준 모델을 따로 만들어 같은 입력으로 돌려 비교했다.

- 기준 모델: `test/reference_model/tube_reference.dart`, `conduit_reference.dart`,
  `cutting_reference.dart` (순수 Dart, 출처는 각 파일 머리말에)
- 비교 검사: `test/reference_compare_test.dart` — `flutter test test/reference_compare_test.dart`
  로 돌리면 차이 표와 요약 줄을 찍는다. 차이가 나도 검사는 실패하지 않는다.
- 이 문서의 숫자는 모두 그 검사 출력에서 가져왔다(2026-09-23 실행, 19개 검사 통과).

**요약 줄:** 비교 3421건, 일치 3055건, 차이 366건(앱이 틀림 106 / 기준이 관행값이라 다름 210 / 정의가 달라 비교 불가 50), 관찰 24건.

- 튜브 마킹 엔진(반경 5가지 × 각 6가지 × 형상 여러 가지, 1,800여 건)은 기준과
  0.5mm 넘게 다른 것이 **없다**. 오프셋·새들·킥·롤링·U벤드·평행 시트의 삼각함수
  셈도 같다. 컷팅 절단 길이·원자재 배치도 같다.
- 차이는 거의 다 **전선관** 쪽이다. 관행 배수와 삼각함수 정확값의 차이(관행값),
  길이를 "꺾이는 점 기준"으로 볼지 "관 등(바깥면) 기준"으로 볼지(정의), 그리고
  표 게인을 각도로 줄이는 방식·새들 수축 더하기·90° 넘는 각(앱이 틀림)이다.

## 4. 값으로 비교 못 한 것 · 관찰 (검사 출력 그대로 요약)

1. 튜브 설정 "테이크업"은 엔진이 안 읽는다. 표에서 테이크업 = 반경이라 값은 같지만, 테이크업만 고치면 아무 일도 없다. (machine_specs.dart:22, tube_bending_engine.dart:133)
2. 반경 0: 경고 없이 마킹 300·700, 절단 900. 반경 0 + 실측 게인 12: 마킹 300·688, 절단 876, 벤드가 먹는 길이 −12로 그대로 셈. (tube_bending_engine.dart:133-172)
3. R100 [500, 90°]: 꼬리 0 → 절단 557.1(경고 없음), 꼬리 50 → 507.1(경고 1건), 꼬리 100 → 557.1. 꼬리를 0→50으로 늘리면 절단이 50 짧아진다. (tube_bending_engine.dart:181-191)
4. 170°(입력 상한) R38.1 [500,170°]×2 꼬리 500: 절단 −15.9, 셋백 435.5, 경고 1건 — 기하로는 맞고 경고도 난다. 179.8° R100 [500]: 절단 −113,477.6 → 화면에서 막는다(엔진은 값을 낸다).
5. 음수 길이 [−100, 90°]: "곧은 부분 음수"로만 잡힌다. NaN 길이·각도: 절단 NaN, 경고 0건.
6. 최소 물림: R38.1 [300,90°][80,90°] 벤드 사이 곧은 부분 3.8mm(최소 물림 30) — 마킹 탭 점검 경고 0건, 입력 탭 검사도 80 ≥ 30이라 통과. 오프셋 시트 45° H30 R38.1: 빗변 42.4 > 30 경고 없음, 실제 곧은 부분 10.9mm. (bend_check.dart:117-122, segment_length_check.dart:69-79, mobile_offset_bottom_sheet.dart:271-273)

9. 전선관 설정 기본값 22mm 게인 81.2 vs 표 82.5. (conduit_settings_page.dart:36, bender_spec_data.dart:11)
10. 유압 벤더는 각도별 셋백 표를 쓰는데 앱은 90° 셋백 하나를 tan(θ/2)로 줄인다. 표가 없어 값 비교 못 함.
11. referenceMark("화살표 (일반)")·bendRadiusWarning은 저장만 되고 어느 셈에도 안 쓰인다. couplingDepth는 읽기만. (conduit_settings_page.dart:46-47)
12. 부속 DB: 스웨즈락 1/2"만 15개, 나머지 규격·제조사는 "직접 입력"뿐. 공제값은 제조사 도면과 대조 못 함. FittingItem.insertionDepth는 셈에 안 쓰인다. (smart_fitting_db.dart)
13. 태블릿용 parallel_shrink_bottom_sheet.dart:88-89는 90°에서 π/2(1.5708)를 곱한다(간격 50 → +78.5, 맞는 값 +50). 이 파일과 offset_bottom_sheet.dart(:225-226 게인 비례 환산), saddle_bottom_sheet.dart(:159 첫 구간 = 축소값, :246-247 비례 환산, :259 게인 더하기), rolling_offset_bottom_sheet.dart는 어디서도 안 부르는 죽은 파일이다.

## 5. 문제점

### P0 — 틀린 셈(현장에서 치수가 어긋난다)

① **전선관 3점 새들: 1번 마킹에 총 수축(양쪽 몫)을 더해 새들 가운데가 장애물 중심을 지나간다.**
   22mm EMT H100 45° 가운데: 가운데가 중심 600에서 639.8(+39.8), 60°: +53.6, H200 45°: +79.6.
   1번 마킹은 그 앞에서 줄어드는 것이 없으므로 더할 것이 없고, 관행(Greenlee)은
   "장애물 중심까지 거리 + 수축(한쪽 몫, 45°는 높이×3/16)"을 **가운데 마킹**에 준다.
   앱은 장애물 중심을 받지도 않는다. 4점 새들도 같은 방식(총 수축을 1번에)이다.
   - 근거: bend_sheet_specs.dart:53-59 (`shrinkToAdd` — 전선관은 기하 축소값 전부),
     mobile_saddle_bottom_sheet.dart:555 (shrink3Pt = 양쪽 합), :201-205 (1번 마킹 = 시작 + shrink3Pt), :606 (4점)
   - 튜브는 addGeometricShrink=false라 해당 없음.

② **전선관 90° 넘는 각의 게인 환산이 터진다.** 22mm EMT 100° 게인 122.7(기하 72.9), 120° 263.3(156.6), 150° 931.5, 170° 3823.8 → [300,170°][300] 절단 −3223.8. 입력 탭이 170°까지 받는다.
   표 게인(등 기준, 82.5)을 (2tan(θ/2) − θ) 비율로 줄이는 식은 90° 아래에서는
   그럭저럭 맞지만 90° 위에서는 tan이 커지면서 등(OD) 몫까지 같이 불어난다.
   - 근거: conduit_marking_logic.dart:20-34, conduit_input_tab.dart:32

### P1 — 빠짐·어긋남(실측으로 정해야 하거나 경고가 없다)

③ **전선관 오프셋 마킹 간격: 앱 안에서 두 모델이 섞였다.** 테이크업은 "CLR + 고정분"으로
   기하 환산하면서(bend_geometry.dart:85-91), 두 마킹 사이에서 빼는 게인은 등 기준
   표 값을 비율로 줄인 값이다(conduit_marking_logic.dart:100-102, 150). 22mm EMT H100
   45°: 앱 간격 133.1, CLR 기하로는 136.5, 관행(게인 안 뺌)은 141.4. 60°: 94.8 / 103.2 / 120.0.
   어느 쪽이 맞는지는 실측 없이 못 정한다. 한 번 꺾어 재서 정하고, 그때까지는
   "관행 간격(높이×배수)"을 고를 수 있게 두는 것이 안전하다.

④ **길이 기준이 파일 안에서 갈린다(교차점 vs 관 등).** conduit_marking_logic.dart:3은
   "꺾이는 점에서 꺾이는 점까지"라 적고, :229-237 보정은 "등(바깥면)까지"로 잰다.
   표 테이크업·게인은 등 기준이라 90° 스텁·절단은 등 기준으로 넣어야 맞고,
   형상 점검(conduitBendCheck, CLR 기하)은 교차점 기준으로 본다. 22mm 90° 절단 300/700:
   등 기준 917.5 vs 교차점 기준 950.9(−33.4). 화면에 "치수는 관 등까지"라고 적어야 한다.

⑤ **튜브 1/2" 제원 표 게인 20.0.** 반경 38.1의 기하 게인은 16.35이고 같은 반경인 5/8"은
   16.3으로 적혀 있다. 자동 채움으로 이 값을 쓰면 90° 하나에 3.65mm 짧게 잘린다.
   - 근거: fitting_data.dart:94-100 (0.5), :101-107 (0.625)

⑥ **최소 물림 길이 경고가 빠진 곳.** 마킹 탭 점검은 곧은 부분이 0보다 작을 때만 말한다
   (bend_check.dart:117-122, bend_path.dart:246-252). 3.8mm(최소 30)도 통과. 입력 탭
   검사(segment_length_check.dart:69-79)와 오프셋·새들 시트 경고(mobile_offset_bottom_sheet.dart:271-273,
   mobile_saddle_bottom_sheet.dart:265)는 교차점 치수(빗변)로 비교해서, 45° H30 R38.1처럼
   빗변 42.4 > 30이면 곧은 부분이 10.9라도 경고가 없다. 비교 대상을 "빗변 − 2·셋백"으로
   바꿔야 한다.

⑦ **반경 0이면 경고 없이 셈한다.** 마킹 300·700, 절단 900(셋백 0). 실측 게인만 있으면
   벤드가 먹는 길이가 −12로 음수인데 그대로. 제원이 비었다는 말이 한마디 있어야 한다.
   - 근거: tube_bending_engine.dart:133-172 (반경 검사 없음)

⑧ **꼬리 0과 짧은 꼬리의 뜻이 다르다.** R100 [500, 90°] 꼬리 0 = 557.1(호 끝까지, 경고 없음),
   꼬리 50 = 507.1(경고). 꼬리를 늘렸는데 절단이 50 줄어든다. 꼬리 0을 "호 끝까지"로 볼
   거면 0 < 꼬리 < 셋백도 같은 값으로 잡거나, 화면에 "꼬리 0 = 벤드 끝에서 자름"이라 적어야 한다.
   - 근거: tube_bending_engine.dart:181-191

⑨ **전선관 제원 표에 출처 없는 줄.** 수동 42·54mm EMT, Rigid 36·42·54mm(bender_spec_data.dart:14-15, 21-23).
   시카고 테이크업은 수동 값 복사(:72-73). 이 규격을 고르면 표 값이 그럴듯하게 채워지지만
   근거가 없다. "표 값 없음 — 직접 재서 넣으십시오"가 맞다.

⑩ **설정값이 안 먹는 곳.** 튜브 테이크업(관찰 1), 전선관 referenceMark·bendRadiusWarning(관찰 11),
   전선관 기본 게인 81.2 vs 표 82.5(관찰 9).

⑪ **부속 DB가 1/2" 스웨즈락뿐이고 공제값 출처가 없다.** 다른 규격은 전부 직접 입력.
   insertionDepth 칸은 셈에 안 쓰인다.

⑫ **U자에 실측 게인을 넣는 방식.** 앱은 90° 두 번(2×(2R − 게인90)), 1/2" R38.1 게인 12.3이면
   127.8mm. 실효 반경의 호로 보면 90.0mm(−37.8). 반경만 쓰면 둘 다 119.7. 180°로 한 번
   꺾어 재 본 값이 없으면 어느 쪽이 맞는지 모른다. 화면 글(u_bend_plan.dart:59-60)대로
   "마킹 탭과 같은 셈"이긴 하다.

### P2 — 편의·정리

⑬ 죽은 태블릿 시트 4개(관찰 13)에 예전 틀린 식이 남아 있다. 누가 다시 연결하면 그대로 살아난다. 지우는 게 낫다.
⑭ 유압 램 이동량 sin(θ/2) 어림, 유압 셋백 tan(θ/2) 환산 — 제조사 표를 넣을 자리가 없다.
⑮ 스프링백이 각도와 상관없이 한 값(튜브 설정 1개, 전선관 규격별 1개). 얕은 각(15~30°)에 3°를 얹으면 과하다.
⑯ 튜브 마킹 탭·현장 탭에 벤드 허용량(R·θ)·게인이 벤드마다 안 보인다(총 게인만).

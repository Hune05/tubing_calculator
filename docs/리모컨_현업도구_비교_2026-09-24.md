# 리모컨 — 현업 도구와 비교 (2026-09-24)

읽은 기준: `bc6d9f2`. 코드를 읽기만 했고 폰·태블릿에서 돌려 보지는 않았습니다.

리모컨이 하는 일: 폰(`MobileRemotePage`)에서 직관·90°·오프셋·새들·롤링 오프셋 값을 넣고 방향을 고르면, 서버 모음 `remote_commands`에 한 건을 쓰고, 태블릿·PC 벤딩 계산기(`CalculatorPage`)가 그 모음을 듣고 있다가 받아서 계산기에 한 줄(길이·각도·방향)을 넣는다.

파일 줄임말(모두 `lib/src/presentation/calculator/` 아래)
- 폰 = `screens/mobile_remote_page.dart`
- 태블릿 = `screens/calculator_page.dart`
- 부품 = `widgets/remote_widgets.dart`

## 견준 도구

| 도구 | 비슷한 점 | 잘하는 것 |
|---|---|---|
| CNC 벤더 작업 전송(공장용 벤딩 소프트웨어) | 사무실·폰에서 값을 만들어 기계로 보냄 | 받을 기계를 고름, 작업 대기열, 받았음·거부 확인, 전송 이력 |
| 크롬캐스트·스포티파이 커넥트 | 폰이 리모컨, 다른 기기가 실행 | 받을 기기를 목록에서 고름, "연결됨" 표시, 한 기기만 받음 |
| 카카오톡 "나에게 보내기"·에어드롭 | 내 기기끼리 보내기 | 내 계정 기기에만 감, 못 가면 바로 알려 줌 |

그쪽 기능은 흔히 알려진 기준이고 직접 돌려 본 것은 아닙니다.

## 1. 잘하는 것 (지킬 것)

- 폰에서 값을 넣는 동안 2D 미리보기와 오프셋·새들·롤링 결과(이동 길이·각도)를 바로 보여 준다(폰 129-201).
- 태블릿은 받은 명령을 대기열에 쌓아 하나씩 처리한다. 동시에 여러 개가 와도 안 잃는다(태블릿 158-183).
- 태블릿이 적용에 성공했는지(`completed`/`failed`)를 다시 서버에 적고, 폰 이력에 "완료"가 뜬다(태블릿 343-347, 폰 305-322).
- 태블릿은 화면을 연 뒤에 온 명령만 받는다. 옛 명령이 다시 실행되지 않는다(태블릿 115, 151).

## 2. 문제점

### 2-1. 값이 틀리게 들어가는 곳 (고쳐야 함)

1. **새들 3점: 폰에 보이는 값과 태블릿에 들어가는 값이 다르다.**
   - 폰은 3점 새들을 "각도의 절반"으로 계산해 보여 준다: 이동 = 높이 ÷ sin(각도/2)(폰 158-167, 주석에 계산기 새들 시트 공식과 맞췄다고 적혀 있음).
   - 태블릿은 받은 각도를 그대로 쓴다: 이동 = 높이 ÷ sin(각도)(태블릿 282-289).
   - 3점인지 4점인지(폰의 안쪽 탭)는 보내지 않는다(폰 254-257·270-283, 기록에 칸 없음). 4점의 폭(val2)도 보내지만 태블릿은 안 쓴다.
   - 예: 높이 100, 각도 45°, 3점 → 폰 화면 261.3 / 태블릿 입력 141.4.
2. **오프셋에서 이동 길이가 높이보다 짧으면 조용히 90°로 들어간다.**
   - 폰(거리 탭)은 이동 < 높이면 각도 칸을 비운다(폰 147-155). 확인(폰 211-229)은 이동 칸이 비었는지만 봐서 그대로 보낼 수 있다.
   - 태블릿은 각도가 0이면 `asin(높이/이동)`을 1로 잘라 90°로 만든다(태블릿 270-281).
   - 각도 탭에서 90° 이상을 넣어도 막지 않는다(폰 결과만 빈칸).
3. **오프셋·새들이 계산기에 "한 줄"만 들어간다.** 태블릿은 어떤 모드든 `_executeMacro` 한 번(길이·각도·방향 한 줄)으로 넣는다(태블릿 259-296). 오프셋은 꺾임 두 번, 새들은 세·네 번인데 나머지 꺾임은 사람이 넣는 것인지 코드만으로는 알 수 없다. **현장에서 쓰는 방식 확인 필요.**

### 2-2. 누구 태블릿으로 가는지 (공유할 때 가장 큰 문제)

4. **받을 기기를 고르지 않는다.** `remote_commands`는 모두가 쓰는 한 모음이고, 태블릿은 조건 없이 전부 듣는다(태블릿 149-153). 두 사람이 앱을 쓰면 내 폰 명령이 남의 태블릿 계산기에도 들어간다. 혼자 쓸 때도 태블릿·PC 둘 다 계산기를 열어 두면 양쪽에 다 들어간다.
5. **시계가 다르면 명령을 조용히 버린다.** 명령 시각은 폰 시계(폰 268), 거르는 기준은 태블릿 시계(태블릿 115)다. 폰 시계가 태블릿보다 늦으면(태블릿이 오래 통신 없이 있었던 경우 등) 새 명령이 "옛 명령"으로 보여 안 들어가고, 폰에는 "전송 완료"가 뜬다.

### 2-3. 보내는 쪽 동작
6. **통신이 없으면 폰이 멈춘다.** `await ...set()`(폰 300-303)은 서버가 받았다고 할 때까지 끝나지 않는다. 통신이 없으면 "전송 중" 흰 장막(폰 415-420)이 영영 안 걷히고 화면을 못 누른다(`AbsorbPointer`). 앱의 다른 화면들은 모두 몇 초 뒤 그만두게 고쳐져 있는데 여기만 빠졌다.
7. **"태블릿 전송 완료!"가 너무 이르다.** 서버에 쓴 순간 띄운다(폰 338-349). 태블릿이 받았는지는 이력의 작은 표시로만 바뀌고, 태블릿이 꺼져 있어도 "완료"가 먼저 뜬다. 태블릿이 `failed`로 적어도 폰은 모른다(`completed`만 봄, 폰 311-312).
8. **보낼 때마다 듣기(listener)가 하나씩 늘고 안 닫힌다**(폰 305-322). 오래 쓰면 쌓인다.
9. **폰 이력은 화면을 나가면 사라진다**(폰 62). 서버에 기록은 남지만 폰에서 다시 볼 길이 없다.
10. **폰의 반경 표시는 폰 설정이다**(폰 92-106, 이름은 `_serverRadius`). 실제 계산은 태블릿 설정으로 한다. 둘이 다르면 폰 미리보기와 태블릿 결과가 다르다.

### 2-4. 쌓임
11. **옛 명령을 안 지운다.** `remote_commands`는 계속 늘기만 한다. 태블릿은 "연 뒤의 것"만 걸러 읽으니 느려지지는 않지만 서버 저장이 쌓인다.

| CNC 작업 전송 | 작업 단위로 보냄 | 오프셋·새들을 꺾임 여러 줄로 한 번에 보내기(현장 확인 뒤) |

## 4. 개선안

### R1 — 값 바로잡기
1. **새들 3점/4점을 보내고 태블릿이 같은 공식을 쓰게.** 명령에 `saddleType`(3/4)과 폭을 넣고, 태블릿은 3점이면 각도/2로 이동을 셈. 더 좋게는 이동·각도 계산을 한 함수로 떼어 폰·태블릿이 같이 쓰게(검사 추가).
2. **오프셋 입력 막기.** 각도는 0<각도<90만, 이동 < 높이면 보내기 전에 "이동 길이가 높이보다 짧습니다". 태블릿도 잘못된 값이면 90°로 만들지 말고 `failed`.

### R2 — 보내기 믿게
3. **통신 없으면 몇 초 뒤 멈춤 풀기.** 쓰기에 시간 제한, 넘으면 "통신이 없습니다 — 태블릿도 통신이 있어야 받습니다".
4. **결과를 기다려 보여 주기.** "보냈습니다 — 태블릿 반영 기다리는 중" → `completed`면 "태블릿에 들어갔습니다", `failed`면 까닭, 10초 넘으면 "태블릿이 받지 않았습니다(계산기 화면이 열려 있는지)". 듣기는 결과가 오거나 시간이 지나면 닫기.
5. **시계 차이 없애기.** 명령에 서버 시각(`FieldValue.serverTimestamp()`)을 같이 적고, 태블릿은 "연 뒤"를 폰 시각 대신 서버 시각으로 거르기(또는 `status == 'pending'`인 것만 받기).

### R3 — 내 기기에만
6. **보낸 사람 uid로 거르기.** 명령에 `uid`, 태블릿은 `where('uid', isEqualTo: 내 uid)`. 익명 로그인(프로필 Q1)이 켜져 있으면 이름만 쓰는 사람도 된다. uid가 없으면 지금처럼 전부 받음.
7. **받을 기기 표시(선택).** 태블릿·PC가 계산기를 열면 "받는 중"을 적고 폰에 보여 주기. 둘 다 열려 있으면 폰에서 하나 고르기.

### R4 — 정리
8. 폰 이력을 서버 명령에서 읽어 오기(내 uid, 최근 20건).
9. 반경 표시를 "이 폰 설정"이라고 이름 바꾸기, 또는 태블릿이 "받는 중"에 자기 반경을 적어 폰이 그것을 보여 주기.
10. 하루 지난 명령 지우기(태블릿이 열 때 내 uid 것 중 오래된 것).

### 넣지 않아도 되는 것
- 블루투스·와이파이 직접 연결(서버 없이). 통신 없는 현장에서는 좋지만 기기마다 권한·연결이 복잡하다. 폰과 태블릿이 둘 다 통신이 되는 곳에서만 쓰는 지금 방식으로 충분.
- 명령 암호화·서명. 규칙(uid)으로 충분.

## 확인하지 못한 것
- 오프셋·새들을 리모컨으로 보냈을 때 현장에서 나머지 꺾임을 어떻게 넣는지(2-1의 3).
- 태블릿 계산기가 한 줄을 넣을 때 새들·오프셋용 각도를 어떻게 해석하는지(벤딩 엔진은 손대지 않는 원칙이라 읽기만 함).

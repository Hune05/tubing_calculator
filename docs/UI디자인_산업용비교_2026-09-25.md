# UI 디자인 — 산업·현장용 최고 수준과 비교 (2026-09-25)

지금 앱 화면(폰 412 폭 스크린샷 32장)과 코드(색·글자·부품 사용 수)를 아래 기준과 견줬다.
장갑 조작(작은 단추), 방향 단추 영어 표기, 납기 D-3 표기는 앞서 빼기로 해 여기서도 다루지 않는다.

## 0. 한 줄 결론

바탕(흰 카드·청록 한 색·넉넉한 여백)은 토스처럼 깔끔하고, 앞 점검들로 넘침·겹침도 거의 없다.
모자란 것은 **"디자인 시스템"이 없다는 것**이다. 화면마다 색·글자·단추·창을 직접 적어서, 같은 뜻이 화면마다
다르게 보이고(파랑 셋, 빨강을 "만들기"에 씀) 색이 상태를 말해 주지 못한다. 산업용 최고 수준(ISA-101 HMI,
Siemens iX, SAP Fiori)은 **토큰 한 벌 + 부품 한 벌 + 색은 상태에만**이 핵심이다.

| 항목 | 지금 | 산업용 최고 수준 | 점수(5) |
|---|---|---|---|
| 기본 모양(여백·카드·정렬) | 깔끔, 토스풍 | 같음 | 4 |
| 색 체계(토큰) | 색 선언 490곳, 색값 112가지, 같은 이름이 파일마다 다른 색 | 역할 토큰 한 벌 | 2 |
| 색의 뜻(상태) | 청록이 단추·선택·링크·성공 모두, 빨강이 "만들기" | 색은 이상·상태에만 | 2 |
| 글자 위계 | 크기 25가지, 굵기 거의 다 굵게 | 6~7단 스케일, 굵기 3단 | 2 |
| 숫자 표시(계측값) | 고정폭 글꼴 70곳, 자리 맞춤 3곳 | 숫자·단위 분리, 자리 고정 | 3 |

## 2. 잘 된 것(그대로 두기)

- 흰 카드·옅은 회색 바탕·청록 한 색 강조. 폰 홈·작업 일지·주간 보고·설정 화면이 한눈에 정돈돼 보인다.
- 아래 고정 주 단추(작업 일지 저장·설정 저장·PDF)가 크고 위치가 같다.
- 선택 칩(작업 유형·결함 유형)이 모양이 같고, 고른 것이 채워져 잘 보인다.
- 앞 점검(U-A~D)으로 겹침·넘침·햇빛 글씨·이름 끊김은 정리됐다.

## 4. 차이와 문제

### D1. 테마가 어두운데 화면은 밝다 → 모든 화면이 색을 직접 적는다
- `main.dart`의 테마가 `ThemeData.dark()`다. 그래서 날짜 고르기·기본 창·드롭다운처럼 앱이 색을 안 준 기본 위젯은
  어둡게, 보라 단추로 나온다(`app_dialog.dart` 맨 위 주석이 이 문제를 적어 둠). 그것을 피하려고 화면마다 색을 직접 적어
  색 선언이 490곳이 됐다.
- 기준: Material 3·Siemens iX는 테마(토큰) 한 곳만 바꾸면 모든 화면이 따라간다.
- 영향: 색 하나(예: 청록을 조금 진하게)를 바꾸려면 수백 곳을 고쳐야 하고, 빠뜨린 곳이 다른 색으로 남는다.

### D2. 브랜드 색이 셋이다
- 청록 `#007580`(대부분), 토스 파랑 `#3182F6`(폰 홈·프로필·알림·차량의 `tossBlue`), iOS 파랑 `#0A84FF`(수평계 전체).
- 프로필 화면의 사람 아이콘·수평계 화면 전체가 다른 앱처럼 보인다.
- 기준: 브랜드 주 색은 하나. 계측 화면(수평계)도 같은 앱의 한 화면으로 보여야 한다.

### D3. 색이 상태를 말해 주지 못한다(가장 중요)
- 청록이 "주 단추·골라짐·링크·완료·진행 중·AUTO 켜짐"을 모두 뜻한다.
- 빨강이 "지우기·기한 넘김"에도, **"이슈 등록하기"(새로 만들기) 큰 단추**에도 쓰인다. 주황은 "보통 우선순위 골라짐"에도,
  "주의"에도 쓰인다.
- 기준: ISA-101은 바탕을 회색으로 두고 **색은 이상 상태에만** 쓴다. Fiori는 상태 색 다섯(좋음 초록·주의 주황·위험 빨강·
  정보 파랑·없음 회색)을 고정한다.
- 영향: 현장에서 빨간 것을 보면 "문제"로 읽어야 하는데, 평소 누르는 단추가 빨가면 경보에 무뎌진다.

### D4. 글자 위계가 약하다
- 크기 25가지, 거의 모든 글이 굵다(보통 굵기는 44곳). 제목·본문·보조가 굵기로 갈리지 않아, 카드 안에서 무엇이 핵심인지
  눈이 먼저 가는 곳이 없다.
- 기준: Carbon·Material은 크기 6~7단(표시 숫자·제목·부제·본문·보조·캡션·라벨), 굵기 3단(보통·중간·굵게).

### D5. 숫자(계측값) 표시가 제각각
- 고정폭 글꼴(`monospace`)이 70곳이다. 한글과 섞이면 글꼴이 바뀌어 폭·굵기가 튄다. 자리 맞춤(tabular figures)은 3곳뿐이다.
- 숫자와 단위(mm, °)의 크기·색 관계가 화면마다 다르다(마킹 탭 큰 숫자, 컷팅 결과, 설정 칸).
- 기준: Fluke Connect·HMI는 "큰 숫자 + 작은 단위", 자릿수 고정(값이 바뀌어도 위치가 안 흔들림).

### D6. 단추 모양이 섞였다
- 같은 "주 행동"이 청록 채움(작업 일지 저장), **검정 두꺼운 테두리를 두른 떠 있는 단추**(새 프로젝트 추가·새 일정)
  *(D-C 때 다시 보니 이 테두리는 시험 환경이 그림자 대신 그리는 검은 선이었다. 실제 앱은 그림자다. 점검 도구를 실제처럼 그리게 고침)*,
  검정 테두리 흰 단추(특수 벤딩 툴), 회색 채움(리모컨 전송 비활성)으로 나온다. 모서리도 15가지다.
- 직접 만든 누름 영역(InkWell·GestureDetector)이 279곳이라 누를 때 물결·눌림 표시가 있기도 없기도 하다.

### D7. 창·알림 부품이 여럿
- 확인 창이 네 갈래(기본 AlertDialog 102, AppDialog, 컷팅 확인창, 지우기 확인창). 모서리·단추 배치(가로/세로, 왼쪽/오른쪽)·
  위험 단추 색이 다르다.
- 알림(스낵바)이 직접 354곳 + 컷팅 알림 117곳. 떠 있는 것/바닥에 붙은 것, 색, 머무는 시간이 다르다.

### D8. 화면 머리(앱바) 모양이 다섯
- 흰 머리(대부분), 청록으로 채운 머리(튜브·형강 컷팅), 짙은 회색 띠(리모컨), 머리 없음(폰 홈), 파랑 버튼 떠 있음(수평계).
- 기준: HMI는 "모든 화면의 틀이 같아야 지금 어디인지 안다". 한 앱 안에서 머리가 바뀌면 다른 앱으로 넘어간 느낌이 든다.

### D9. 아이콘이 세 벌
- Material(채움·굵기 다양), Lucide(가는 선), 자체 그림(AppGlyph)이 한 화면에 섞인다(예: 폰 홈 메뉴는 자체 그림, 목록 화살표는 Material).

### D10. 야간(어두운) 보기가 없다
- 플랜트 실내·야간 작업, 밝기를 낮춘 폰에서는 흰 화면이 눈부시다. 햇빛(고대비) 보기도 현장 탭에만 있다.
- 기준: Siemens iX는 어두운 테마가 기본이고 밝은 테마를 토큰으로 바꾼다. 현장 앱들도 어두운 테마를 준다.

### D11. 불러오는 중에 빈 화면 + 빙글이
- 목록 화면 63곳이 가운데 빙글이만 보인다(내 프로젝트·내 일정 스크린샷). 통신이 없으면 오래 빈 화면이다.
- 기준: Procore·Fieldwire는 폰에 있는 자료를 먼저 보이고 뒤에서 새로 고친다. 적어도 목록 모양(스켈레톤)을 먼저 보인다.

### D12. 글꼴이 기기마다 다르다
- NotoSansKR을 앱에 넣어 두었지만 화면 테마에 안 써서, 화면은 폰 기본 글꼴(삼성·LG·픽셀마다 다름)이고 PDF만 NotoSansKR이다.
  같은 화면이 폰마다 폭이 달라 줄바꿈 위치가 달라진다.

### D13. 빈 상태 모양이 다르다
- 튜브 입력 탭은 가운데 회색 글 한 줄, 전선관 입력 탭은 아이콘+제목+설명 카드. 같은 뜻이다.

## 5. 제안(묶음)

### D-A. 색·글자 토큰과 밝은 테마(먼저, 중간~큼) — ✅ 고침(2026-09-25)
- `lib/src/core/theme/app_tokens.dart`(색 역할·글자 7단·굵기 3단·모서리 3단·간격), `app_theme.dart`(밝은 Material 3, 청록, NotoSansKR 가변 글꼴 — 굵기 400/600/800이 제대로 나오는 것을 확인).
- `ThemeData.dark()`를 없앴다. 전후 스크린샷에서 튜브 설정 탭 검은 바탕, 알림 점검의 옅은 분홍·보라 단추, 일지 칩·주간 보고 글이 흐리던 것이 사라졌다.
- 앱 글꼴로 바뀌며 드러난 넘침 4곳을 고쳤다(글꼴이 굵기를 제대로 그리자 폭이 늘어난 곳).
- 흩어진 색 상수 455곳(112파일)을 토큰으로 바꿨다(같은 역할의 비슷한 색 두세 가지를 하나로). 배치도 그림 색은 그림 비교 테스트 때문에 그대로.
- 글자 크기 단계는 기본 글 모양을 한꺼번에 바꾸지 않고, D-C에서 부품을 옮길 때 이름으로 쓴다(한꺼번에 바꾸면 화면마다 넘칠 수 있음).
- `lib/src/core/theme/`에 **토큰 한 벌**: 역할 색(주·주 위 글·표면·표면 위 글·옅은 글·선·좋음·주의·위험·정보),
  글자 7단(숫자 표시 40/28, 제목 20, 부제 17, 본문 15, 보조 13, 캡션 12), 굵기 3단(400·600·800), 모서리 3단(8·12·20), 간격 4의 배수.
- 앱 테마를 **밝은 Material 3**(청록 `#007580` 기준 `ColorScheme`)로 바꾸고 NotoSansKR을 `fontFamily`로. 기본 위젯이 앱 모양으로 나온다.
- 기존 색 상수(`makitaTeal`·`_teal`·`tossBlue`·`slate600` …)를 토큰으로 **자동 치환**(스크립트) → 화면별로 눈으로 확인. 테스트와 UI 점검 도구 스크린샷으로 전후를 견준다.

### D-B. 색의 뜻 정하기(작음, 바로 할 수 있음) — ✅ 고침(2026-09-25)
- 색의 뜻을 `lib/src/core/theme/status_colors.dart`에 적었다(kBrand·kOk·kCaution·kDanger·kIdle).
- 이슈 등록하기(폰·PC) 빨강 → 청록, 우선순위 "보통" 주황 → 청록(긴급만 빨강, 여유 회색), 물림 경고 "무시하고 추가" 빨강 → 주황.
- 폰 홈·프로필·프로필 사진·알림·차량의 토스 파랑, 수평계의 iOS 파랑 → 청록.
- 오류 알림(스낵바)의 빨강과 지우기 단추의 빨강은 뜻이 맞아 그대로 두었다.
- 청록 = 누르는 것·골라짐, **초록 = 완료·수평**, **주황 = 주의·기한 임박**, **빨강 = 지우기·기한 넘김·경보만**, 회색 = 없음·꺼짐.
- "이슈 등록하기" 단추를 청록으로(빨강 → 청록), 우선순위 "긴급"만 빨강 칩.
- 폰 홈·프로필·알림·차량의 파랑(`#3182F6`)과 수평계 파랑(`#0A84FF`)을 청록으로.

## 4. 사용자가 정한 것 (다시 묻지 말 것)

- **부스바·접지바·케이블 트레이는 더 고도화하지 않는다.** 요청한 것과 계산 틀림만 다룬다(그림 화살표·입체 같은 작업도 안 함).
- 튜브·전선관 벤딩이 앱의 중심이다. 다만 **계산 엔진(`tube_bending_engine` 등)은 사용자 판단 없이 손대지 않는다.**
- 기준 그림을 주면 **배치까지 그대로** 따른다(롤링 오프셋 때 다르게 만들어 지적받음).
- 그림 확대 화면·그림 고정은 안 한다. 그림 칸은 태블릿에서만 1.3배.
- 한국어 습니다체, 현장 말, 현장 영어 용어는 영어 그대로(Rise·Run·Travel 등).

## 6. 작업할 때 함정 (이번에 겪은 것)

- **그림 시험은 실제 글꼴로**: 시험 기본 글꼴(Ahem)은 글자가 1.6배 넓어 값표 겹침을 잘못 판단한다. `FontLoader('NotoSansKR')`로 `assets/fonts/NotoSansKR-Bold.ttf`를 불러 렌더링해서 본다.
- **"값에 따라 모양이 바뀌는가"는 관 색(#007580) 범위로 검사**한다(`test/guide_values_driven_test.dart`). 픽셀 차이 개수만 세면 글자만 바뀐 것도 통과한다. 오른쪽 위 다시 보기 단추는 제외.
- **`dart format`을 파일 전체에 돌리지 말 것** — 기존 파일이 통째로 바뀌어 차이가 커진다. 고친 부분만 손으로.
- 이 환경의 bash 심의 일부 긴 heredoc이 오류를 낸다. 스크립트는 파일로 쓰고(Write 도구) `node 파일.js`로 돌렸다. 소스 파일은 CRLF일 수 있어 패치 때 줄바꿈을 보존한다.
- 폰·태블릿 조작: 스와이프 직후 바로 탭하면 관성 스크롤을 멈추는 데만 쓰여 칩이 안 눌린다 → 3초 기다린다. 폰 스크린샷은 `screencap -d 4630946213010294403`, 보이는 좌표 ×1.16이 실제 좌표.
- 숫자판(`MakitaNumpadGlass`)을 쓰는 14곳은 모두 위에 그림이 있는 특수 벤딩 시트다. 숫자판 모양을 바꾸면 전부 같이 바뀐다.
- 숫자판 안 입력 칸 시험은 `ensureVisible` 먼저, 숫자판 닫기는 `find.byIcon(Icons.close).last`.

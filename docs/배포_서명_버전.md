# 앱 나눠 줄 때: 서명 키·버전·앱 id (점검 29번, 2026-09-25)

## 왜 필요한가
- 예전에는 배포판도 **디버그 키**로 서명했다. 디버그 키는 빌드한 컴퓨터마다 달라서, 다른 컴퓨터(또는 클라우드)에서 만든 APK는 이미 깐 앱 위에 업데이트가 안 되고 **지우고 다시 깔아야** 했다. 그러면 폰에만 있는 설정·임시 저장이 사라진다.
- 버전이 늘 `1.0.0+1`이라 어느 폰에 어느 빌드가 깔렸는지 알 수 없었다.

## 1. 서명 키 한 번 만들기(한 사람이 한 번)
```
keytool -genkey -v -keystore ~/upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```
- 이 `.jks` 파일과 비밀번호는 **잃어버리면 같은 앱으로 업데이트를 영영 못 한다.** 두 곳 이상에 보관한다.
- git에는 올리지 않는다(`.gitignore`에 `*.jks`, `key.properties`가 들어 있음).

## 2. 빌드하는 컴퓨터마다 `android/key.properties` 두기
`android/key.properties.example`을 `android/key.properties`로 복사해 값을 채운다.
```
storePassword=…
keyPassword=…
keyAlias=upload
storeFile=/절대/경로/upload-keystore.jks
```
- 이 파일이 있으면 `flutter build apk --release`가 이 키로 서명한다(`android/app/build.gradle.kts`).
- 없으면 예전처럼 디버그 키로 서명한다(그 컴퓨터에서만 업데이트된다).

## 3. 나눠 줄 때마다 버전 올리기
- `pubspec.yaml`의 `version: 이름+번호`에서 **`+` 뒤 번호는 매번 1씩 올린다**(안드로이드는 이 번호가 더 커야 업데이트를 받는다).
- 지금 값: `1.1.0+2`. 앱 로딩 화면에 `v1.1.0`이 보인다.

## 4. 처음 한 번은 지우고 다시 깔아야 한다
- 지금 폰에 깔린 앱은 디버그 키로 서명돼 있다. 새 키로 서명한 첫 빌드는 **한 번만** 지우고 깔아야 한다. 그 뒤로는 업데이트로 깔린다.
- 지우기 전에: 튜브 설정은 프로필의 "설정 보관"으로 서버에 올려 두고, 새로 깐 뒤 "서버에서 불러오기"를 누른다.

## 5. 앱 id(`com.example.tubing_calculator`)를 바꿀 때(지금은 그대로 두기로 함)
바꾸면 **다른 앱**이 된다(옛 앱과 따로 깔림). 할 때는 이 순서로:
1. Firebase 콘솔 → 프로젝트 설정 → Android 앱 추가 → 새 id(예: `com.회사.tubingcalculator`) 등록.
2. 새 `google-services.json`을 받아 `android/app/`에 바꿔 넣는다.
3. `android/app/build.gradle.kts`의 `namespace`, `applicationId`를 새 id로.
4. `android/app/src/main/kotlin/…/MainActivity.kt`의 `package`와 폴더 경로를 새 id로.
5. 구글 로그인을 쓰면 Firebase에 새 앱의 SHA-1(서명 키 지문)을 넣는다: `keytool -list -v -keystore ~/upload-keystore.jks -alias upload`.
6. 옛 앱을 지우고 새 앱을 깐다(설정은 위 4번처럼 서버로 옮긴다).

## 참고
- 날씨 API 키가 코드에 들어 있다(폰 홈). 개인용이면 괜찮고, 널리 나눠 주면 누구나 꺼낼 수 있다.
- 이 저장소의 클라우드 환경에는 Android SDK가 없어 서명 설정으로 APK를 직접 빌드해 보지는 못했다. 처음 빌드할 때 `flutter build apk --release`가 되는지 확인한다.

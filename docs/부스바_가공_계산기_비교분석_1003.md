# 부스바 가공 계산기(절곡·접지바) 상용 도구 비교 분석 (2026-10-03)

조사 방법: 웹 검색과 페이지 열람. "확인"은 페이지를 직접 연 것, "검색 요약"은 검색 결과 문구만 본 것, 못 찾은 것은 "확인 못 함". 상용 제품 내부 동작은 공개 자료 밖이라 알 수 없다.

## 1. 상용 도구 지형

## 2. 우리 앱의 위치

**강점**
- 현장에서 폰·태블릿으로 바로 쓴다(설치형 CAD·기계 내장 CAM과 다른 자리).
- 한 화면에서 전개 길이 + 꺾기 선 + 구멍 위치(접지·챙·러그) + 판넬 취부 자리 + 볼트 세트 + PDF 지시서를 낸다. 공개 도구에서는 이 조합을 확인하지 못했다.
- 구멍과 꺾기선 거리 주의, 저장한 규격, 카톡·PDF 공유(EHRT가 내세우는 "최소 거리 검증"·"부품 저장"과 같은 방향).
- 근거가 약한 값에 "한 곳 자료", "임의 값"을 화면에 밝혔다.

**약점**
- 상용 CAD/CAM은 기계로 데이터를 넘긴다(NC·DXF). 우리는 사람이 읽는 지시서만 낸다.
- 실제 벤더로 꺾은 시험으로 값을 검증한 적이 없다(아래 §3-1).

## 3. 문제점·부족한 기능과 개선안

### 3-1. 검증과 신뢰 (가장 중요)
| 문제 | 설명 | 개선안 |
|---|---|---|
| 실제 꺾기 시험으로 검증 안 됨 | 식은 일반 굽힘 공제식이라 맞지만 k=0.4, 반경=두께, 스프링백 0은 가정이다 | **시험 조각 실측 입력 → k와 스프링백 역산**("시험 조각 보정" 화면). 벤더 어댑터 반경·보정값을 "벤더 프로필"로 저장 |
| 스프링백 미반영 | 업계 자료(PayaPress 한 곳)에 경질 구리 90° 약 5~8°, 풀림 1~3°. 우리 앱은 문구만 있다 | 재질 상태(연질·경질) 선택 + 과꺾기 각도 표시. 값은 "한 곳 자료·시험으로 맞추기"로 밝힘 |
| 꺾는 순서 근거 없음 | "다리 두 곳을 먼저 내리고 챙을 꺾는다"는 내가 정한 순서이며 벤더 날 간섭은 검토하지 않았다 | 순서를 단정하지 말고 "벤더에 걸리면 바꾸십시오"로 낮추거나, 4곳 꺾기 간섭 검사(몸체 폭·다리 높이 대비 벤더 개구부) 추가 |

### 3-2. 구멍 규칙이 업계 관행보다 느슨함
| 항목 | 우리 앱 | 공개 자료 | 개선안 |
|---|---|---|---|
| 구멍 가장자리 ↔ 꺾기선 | 두께 2배 미만이면 주의 | 일반 판금 자료 여러 곳: 지름 1" 미만 2T+R, 1" 이상 2.5T+R(R=T면 약 3T). 구리 부스바 한 곳: 구멍 지름의 2배(중심 기준) | 기준을 **2T+R**로 올리고 "필요 거리 vs 실제 거리"를 표로 표시. 일반 판금 규칙임을 밝힘 |
| 구멍 ↔ 막대 가장자리 | 끝 여유 25mm(임의) | 펀칭 구멍은 2T 권장, 최소 1T | 끝 여유 기본을 근거 있는 값(≥2T)으로 하고 미달 시 주의 |
| 구멍 ↔ 구멍 | 중심 12mm(사용자 지시) 이상, 겹침 검사 | 가장자리 사이 최소 1T, 권장 2T(한 곳) | 12mm(사용자 지시)는 유지, 가장자리 사이 간격이 1T 미만이면 추가 주의 |
| 최소 반경 | CDA 한 곳 두께 10mm 이하 1배 | Rittal R≥T, PayaPress 1~2T(두께별) | 두께별 표(1T/1.5T/2T)로 확장, 경고에 출처 두 곳이 같은 부분만 "확인" 표기 |

위 일반 판금 규칙은 구리 부스바 전용 표준이 아니다. 부스바 규격(DIN 43673 등)·제조사 매뉴얼의 규정은 찾지 못했다.

### 3-3. 출력과 연동
| 부족 | 개선안 |
|---|---|
| DXF·CSV 출력 없음(펀칭기·CNC·Eplan 연동 불가) | 전개도 DXF(막대 외곽, 구멍 원, 꺾기선)와 CSV(구멍 좌표) 내보내기. 현장 펀칭 기계 입력용 |
| PDF만 있고 이력이 없음 | 만든 지시서를 이름·날짜로 목록 보관(저장한 규격과 함께) |
| 부품표·집계 없음 | 여러 저장 규격을 골라 볼트 세트·구리 무게·막대 길이를 합산하는 "자재 집계"(견적·발주용) |
| 단위 mm만 | inch 전환(NEMA 규격 구멍·피치 사용 시 편의) |

### 3-4. 형상 기능
| 부족 | 개선안 |
|---|---|
| 구멍 형태가 원뿐 | 장공(슬롯) 추가 — 열팽창·위치 조정용 |
| 줄이 최대 2줄, 모양 고정 | 3줄·줄별 개수·피치 지정, 막대 한쪽만 구멍 |
| 챙 길이만 좌우 다름, 다리 높이는 같음 | 좌우 다리 높이도 따로(비대칭 모자) |
| 접지 구멍 몰기가 왼쪽만 | 오른쪽·양끝 선택 |
| 알루미늄 부스바 없음(구리만) | 근거 값이 서로 달라 보류했던 것. 값이 정리되면 추가 |
| 3D 미리보기 없음 | 우선순위 낮음(2D 옆모습·위에서 본 모양으로 충분) |
| 상별(R·S·T·N) 세트 생성 없음 | 특허 개념. 같은 규격을 상별로 복제·이름 붙이기 정도로 축소 |

### 3-5. 코드·유지보수
- `groundBar` 한 함수가 약 500줄이고 접지바 화면이 1,700줄이다. 구멍 생성·검사·꺾기를 나눠야 시험·수정이 쉽다.
- 절곡 화면과 접지바 화면의 칩·입력 구성이 중복이다(저장 창만 공용으로 합침).
- 근거 문서(docs)에 부스바 가공 항목이 없다. 이 문서가 처음이다.

## 4. 도입 제안 우선순위

| 순위 | 기능 | 이유 | 비용 |
|---|---|---|---|
| 1 | **시험 조각 보정(k·스프링백 역산) + 벤더 프로필** | 가정 값을 실측으로 바꾸는 유일한 방법. 정확도가 제일 크게 오른다 | 중 |
| 2 | **구멍 규칙 정리(2T+R, 가장자리 1~2T, 필요 거리 표)** | 근거 있는 값으로 현장에서 가공 불량을 줄인다 | 소 |
| 3 | **DXF/CSV 내보내기** | 펀칭·CNC로 직결, 상용 도구와 가장 큰 격차 | 중 |
| 4 | 자재 집계(저장 규격 합산) | 견적·발주 편의 | 소~중 |
| 5 | 꺾기 간섭·순서 검사 | 모자 4곳 꺾기의 근거 없는 순서 안내를 해소 | 중 |
| 6 | 장공·3줄·좌우 다른 다리 높이·몰기 방향 | 사용자가 계속 요청하는 형상 확장 | 중 |
| 7 | inch 단위, 알루미늄 | 값 정리 후 | 소~중 |

## 5. 한계와 확인 필요
- 상용 제품의 세부 기능(K-factor 값, 스프링백 방식, 구멍 규칙의 구체 값)은 공개 자료에 없어 비교하지 못했다.
- 구멍·가장자리 규칙은 일반 판금 자료이며 구리 부스바 전용 표준 값이 아니다. 구리 전용 수치는 제조사 블로그 한 곳이다.
- 우리 앱의 모든 계산 결과는 실제 벤더·펀칭기로 시험한 적이 없다. 시험 조각 확인 전까지는 참고값이다.
- 위 개선안은 제안일 뿐이며 어느 것도 구현하지 않았다.

# 야간 작업 지시서 (2026-09-23)

사용자가 자는 동안 **묻지 않고 끝까지** 처리한다. 막히면 그 일은 건너뛰고 기록한 뒤 다음 일로 넘어간다.
아침에 사용자가 이 문서 맨 아래 "결과"만 읽으면 되게 한다.
가장 큰 일은 **C(앱 전체 점검·수정)**다. A·B는 짧게 끝내고 남은 시간은 C에 쓴다.

## 0. 꼭 지킬 것 (어기면 안 됨)

1. **설명·보고·커밋 메시지는 한국어로만.** 화면 글은 습니다/십시오 체, 현장 말(잔재·곤질레다·커플링…). 내가 지은 말 금지.
2. **벤딩 계산 엔진(마킹 값) 건드리지 않기.** `tube_bending_engine.dart`, 전선관 마킹 셈, `bend_path.dart`. 테스트 기준값이 바뀌는 수정은 하지 않는다.
3. **진짜 자료 보호.** 폰의 루마·H2(튜브), 전선관(형강), 잔재 목록, 서버에 저장된 배치도("현장 레이아웃_22일" 등)는 절대 고치지 않는다.
   시험은 임시 저장(이어하기)으로만 하고, **시작 전 prefs 백업 → 끝나면 되돌리고 md5 비교.**
4. **폰에서 보내기·공유·로그인·결제·"한 번만/항상" 고르기는 누르지 않는다.** 공유 창에 카톡 대화방이 뜨면 뒤로 가기.
5. **사용자가 폰을 쓰는 중이면 손 뗀다.** 설치·강제 종료 전에 화면을 두 번(5초 간격) 찍어 바뀌는지 보고, 앱 화면이 움직이면 설치를 미룬다.
6. `dart format`은 고친 파일만. `git add`는 파일 이름을 적어서(`.claude/`는 올리지 않음). 커밋 끝에 `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`(지금 모델 이름).
7. 일 하나 끝날 때마다: `dart analyze lib test` → `flutter test`(전부 통과) → APK 빌드(`. tool/keys.local.sh && flutter build apk --debug --dart-define=KAKAO_REST_KEY=$KAKAO_REST_KEY`) → 폰 확인(가능하면) → 커밋 → push.

## 1. 미리 정해 둔 것 (묻지 않는다)

- 스키드 정면·측면: 부품은 평면에 하나(평면 기준). 보는 쪽에서 가까운 부품을 위에, 가까운 부품에 반 넘게 가려지는 뒤 부품은 테두리를 **점선(숨은선)**으로 위에 그린다. 관리 → "가려진 부품 보이기"를 끄면 점선을 안 그린다. 기본은 켜짐.
- 앞·뒤 기준: 정면 = 평면 아래쪽(y 큰 쪽)에서 본다, 좌측면 = x=0 쪽, 우측면 = x 큰 쪽(좌우 뒤집어 그림). 지금 셈과 같다.
- 곤질레다 치수는 대략 값 그대로(사용자가 실물 재서 알려 주기로 함). 새 치수를 지어내지 않는다.
- 새 단추·메뉴 이름이 필요하면 앱에 이미 있는 말을 쓴다. 이미 있는 말이 없으면 만들지 않고 "아침에 물을 것"에 적는다.

## 2. 할 일 (위에서부터 차례로)

### A. 스키드 정면·측면: 그쪽에서 보이는 것만 보이게 (먼저)
- 문제: 지금은 평면 부품이 모두 같은 진하기로 겹쳐 그려져, 뒤쪽 부품과 앞쪽 부품이 구분되지 않는다(엑스레이처럼 보임). 누르면 뒤 부품이 잡힐 수도 있다.
- 고칠 것: 보는 쪽에서 먼 것부터 그리기(가까운 것이 위·먼저 잡힘), 가려진 뒤 부품 테두리는 점선, "관리" 창에 "가려진 부품 보이기" 켜고 끄기(도면 하나에 하나, 임시 저장에 남김).
- 완료 기준: 테스트(가까운 것이 위, 가려진 것 점선/끄기, 좌·우측면 앞뒤가 반대), 폰에서 앞뒤로 겹친 두 부품 확인.

### B. 스키드 남은 것
1. 곤질레다·커플링·유니온 **좌우 뒤집기**(허브가 반대쪽): 편집 칸에 단추. 모양만 뒤집고 크기는 그대로. 저장 칸 하나 추가(예전 도면은 그대로 열려야 함).
2. 정면·측면 **고정 치수 측정**에 평면 부품도 잡히게(그 면에서 본 자리로 잰다). 어렵거나 저장 구조를 크게 바꿔야 하면 건너뛰고 기록.
3. 경로 입력 화면 작은 도면의 점선 네모를 부품 모양으로(SkidPartPainter 재사용).

### C. 앱 전체 점검 → 문제 고치기 (가장 큰 일)

앱 전체(화면 폴더 22개, 약 13만 줄)를 **화면 묶음별로 차례대로** 읽고, 찾은 문제를 고친다.
한 묶음이 끝날 때마다 테스트·빌드·커밋·push하고 결과 표에 한 줄씩 적는다.

**점검 기준 (묶음마다 같은 눈으로 본다)**
1. **자료가 사라지거나 틀어지는 것(제일 먼저):** 저장 안 되고 사라짐, 앱 껐다 켜면 기본값으로 돌아감, 비동기 읽기 전에 저장해서 0·빈값으로 덮임(예전 튜브 반경 0 버그와 같은 꼴), 두 번 저장·두 번 차감, 지우기 되돌리기 없음.
2. **멈춤·빨간 화면:** null 강제(`!`), 빈 목록 `.first`, 숫자 변환 실패(`int.parse`), 화면 닫힌 뒤 setState·context 사용(`mounted` 확인 빠짐), 통신 없을 때(발전소) 무한 로딩.
3. **좁은 폰(344dp)·글자 크게에서 넘침·잘림:** 단추·제목이 잘리거나 노란 줄무늬.
4. **셈이 화면마다 다름:** 같은 값을 두 곳에서 따로 계산(예전 재고 차감 세 벌처럼). 엔진 셈은 고치지 말고 "화면이 엔진 값을 다르게 보여 주는 것"만.
5. **화면 글:** 영어·기계 말·"~요" 끝맺음·지은 말이 남은 것. 바꿀 말이 앱에 이미 있을 때만 바꾸고, 없으면 "아침에 물을 것"에.
6. **죽은 코드:** 어디서도 안 부르는 화면·함수(지우기 전에 grep으로 두 번 확인, 서버 자료는 안 지움).
7. `dart analyze` 경고·info(동작이 안 바뀌는 것만): 안 쓰는 import·함수, 늘 참인 null 비교, if 중괄호, `print` → `debugPrint`.

**고치는 규칙**
- 고치기 전에 그 문제를 **재현하는 테스트를 먼저** 쓰고(실패 확인), 고친 뒤 통과를 본다. 테스트로 못 잡는 것은 커밋 메시지에 까닭을 적는다.
- 한 번에 크게 바꾸지 않는다. 한 문제 = 한 커밋(작은 것은 묶음당 한 커밋).
- 엔진 셈·서버 자료 구조·로그인·결제·서버 규칙은 손대지 않는다 → 찾으면 "아침에 물을 것".
- 마킹 값·재단 결과·재고 수가 바뀌는 수정은 하지 않는다(현장 결과가 바뀐다) → "아침에 물을 것".
- 폰 확인은 묶음마다 한 번(TEST 프로젝트·임시 저장만, 끝나면 되돌림). 진짜 프로젝트 요약 줄(전선관 2건·4.7m·28.3kg, 루마 0회·0.0m, H2 4회·1.1m, 잔재 2개·7350mm)이 그대로인지 끝에 확인.

**결과 적는 법:** 아래 "점검 결과" 표에 묶음마다 [찾은 것 / 고친 것 / 못 고친 것과 까닭]을 적는다.
